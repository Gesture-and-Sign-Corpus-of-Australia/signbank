# Signbank

## Setup
To setup your Signbank development environment:

  * Install Elixir, the recommended way is: (other methods are [outlined here](https://elixir-lang.org/install/#version-managers))
    * Start by installing [`mise` version manager](https://github.com/jdx/mise)
    * Run `mise use -g erlang elixir`
    * Run `mise install` in the root of this repo (This will install the correct versions of both Erlang and Elixir)
  * Run `mix setup` to install and setup dependencies
  * Start Phoenix endpoint with `mix phx.server` or inside IEx with `iex -S mix phx.server`

Now you can visit [`localhost:4000`](http://localhost:4000) from your browser.

### Postgres
Postgres will require a few tweaks before use. At the top of `dev.exs`, you'll see the following lines:

``` elixir
config :signbank, Signbank.Repo,
  username: "postgres",
  password: "postgres",
  hostname: "localhost",
  database: "signbank_dev",
```

These indicate that the username and password values `postgres` will be used to log into the `signbank_dev` database on `localhost`. Postgres does not include a password for the default `postgres` user, so we'll have to set one ourselves. Run the following:

``` sh
sudo -u postgres psql # log into psql as postgres
postgres=# \password postgres # set the password interactively
Enter new password: postgres
postgres=# \q # exit psql
```

### Env File
The included `.env` file in the project's home directory should be sourced before running for full functionality. Without this step, video definitions for signs will not display. The project's `just` file does this automatically.
``` sh
source .env
```

### Technician Login
In order to edit sign entries and process the corpus, you will need to create an account with the `tech` role. This means creating an entry in the `users` table, which requires creating a password hash with bcrypt. For the password `hunter2`, we can use the unix utility `htpasswd` to generate a hash:
``` sh
htpasswd -nBC 10 foobar # username is not relevant for our usecase
New password: hunter2 # password is hidden in real usage
Re-type new password: hunter2
foobar:$2y$10$6pRer3xaIldVa3CAO296se0dkjEY0fksy.FnmvVtsHjgqhSDltPeG
```
We do not need the username field, and Postgres does not support the [hash version marker](https://en.wikipedia.org/wiki/Bcrypt#Versioning_history) generated by this command. Remove `foobar` and change `$2y$` to `$2a$` to produce the output `$2a$10$6pRer3xaIldVa3CAO296se0dkjEY0fksy.FnmvVtsHjgqhSDltPeG`. 

The password is now ready to be inserted into the database. The `confirmed_at`, `inserted_at`, and `updated_at` fields don't matter for development use, so copying from existing entries is fine. The final SQL statement should look something like this:
``` sql
INSERT INTO public.users
(id, email, hashed_password, confirmed_at, "role", inserted_at, updated_at)
VALUES(nextval('users_id_seq'::regclass), 'user@example.com', '$2a$10$6pRer3xaIldVa3CAO296se0dkjEY0fksy.FnmvVtsHjgqhSDltPeG', '2026-03-18 22:41:11.000', 'tech', '2026-03-18 22:41:11.000', '2026-03-18 22:41:11.000');
```

## Deployment

Auslan Signbank is hosted on an Ubuntu VM on the Australian Research Data Common's cloud, Nectar. It should work with any Linux server, although you will need to install and setup some things manually:
- Postgres
- A reverse proxy, since Signbank is not built to communicate over HTTPS directly. I recommend Caddy since it handles TLS certificates automatically. Nginx will work if you'd prefer.
- Tailscale (optional). Allows you to connect to the database from your local machine, without exposing it to the internet.
